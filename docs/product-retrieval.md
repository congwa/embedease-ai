# 商品检索与增量索引

商品查询使用生效的 Embedding 配置发送原文，第三方兼容接口不接收 OpenAI tokenizer 的 token ID。入库和查询必须使用相同模型、维度及编码。

## 旧索引迁移

原有 token ID 编码索引不能直接复用。先备份配置和数据库，设置一个新的 `QDRANT_COLLECTION`，对全部商品执行 `backend/scripts/import_products.py`，核对数量和真实问题召回后，再让运行服务使用新集合。保留旧镜像、配置和集合供回滚；回滚时代码和集合必须同时恢复。

## 查询与事实

向量查询异步执行，候选按商品 ID 聚合，再读取 SQL 最新名称、价格和规格。已从 SQL 删除的商品不会被推荐。明确数字预算和工具的价格参数取交集；分类参数使用库内分类。关键词仅参与排序，不以字面匹配清空语义候选。启用 Rerank 时排除低于 0.05 的相关性结果。详情和对比按 SQL 主键查询，价格过滤直接查询全量 SQL 商品。

长描述按 `CHUNK_SIZE` / `CHUNK_OVERLAP` 分块，每块保留商品身份。返回匹配资料保留最多两个完整命中块，摘要单独使用 SQL 摘要，避免命中长文后因截断丢失依据。

## 更新与回收

入库逐件商品先完成全部嵌入，再写入由商品 ID、内容版本和块序号生成的稳定向量 ID，最后只清理同一商品的旧块。失败会抛错，重跑同批次可幂等清理；不会清空其他商品。SQL 删除后如需物理清理向量，调用 `remove_product_vectors(product_id)`。旧编码或其他模型的非空集合会拒绝增量写入，需新建集合完整重建。

## 验证

在 `backend/` 执行 `uv run python scripts/verify_product_stability.py`，验证原文编码、异步初始化、SQL 事实、预算、聚合、精确详情及增量失败重试。另运行 `uv run python scripts/verify_chat_concurrency.py` 检查聊天并发隔离。线上验收使用真实模型与独立 QA 会话，核对召回、无结果、价格、卡片和事件循环延迟。
